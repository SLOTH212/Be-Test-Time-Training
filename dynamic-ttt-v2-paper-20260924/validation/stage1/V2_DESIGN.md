# Reference executor V2: Stage-1 core robustness revalidation

V2 removes trajectory-dependent standard/functional routing at the five candidate layers [0,6,12,18,24]. Every trajectory retains all five TTT modules, runs with model TTT mode enabled, initializes effective weights from the checkpoint, and uses the same functional chunk, tail and generation implementation. An attempted standard-path call at a candidate layer now raises an error. Non-candidate layers keep their historical implementation.

The action sequence controls only each chunk's update mask. An inactive candidate layer reads and retains its current effective weight through the same functional path. Active chunks use the unchanged historical ttt_chunk_step, including contextual targets, BF16 arithmetic, clipping, and apply-then-update ordering. Updates remain out of place. Incomplete tail and generation read accumulated weights without writes. Fresh model.generate caches and a new Evaluator are used for each full replay; no candidate result cache is used (force=True).

The source diff removes the evaluator's temporary deletion of unused TTT modules, its all-OFF TTT-mode switch, and its synthetic standard-layer event records. The latter are no longer needed because all candidate layers generate real functional events. The scorer, tokenizer, generation budget, greedy settings, SDPA, checkpoint, non-candidate layers, update rule and action/chunk semantics are unchanged. No unrelated executor fixes are included. Historical files remain read-only.

Precheck instrumentation reuses the preceding execution suite's trace collector and copied TTT core. The only update intervention is exact force-zero after proposal computation, restricted to zero-write validation. Trace hooks preserve the underlying forward arithmetic. Validation additionally captures every generation logit and each newly appended generation KV token. In formal replay the uninstrumented V2 runner calls the original historical TTT core; no force-zero intervention is installed.

Prechecks use exactly the prior formal32, without reselection: four same-Native repeat pairs; Z_OFF/Z_NATIVE/Z_ALL on all32 (two comparisons to the same Z_OFF baseline, exact equality implies all-three equality); the first five samples' three frozen E3 families (15 prefix pairs); one old E4 case per candidate layer (five cases). Every run checks writable checkpoint tensor digests. A nonexact zero-write comparison or other failed precheck blocks the173 replay and preserves evidence.

The formal stage executes173x8 trajectories in fixed sample/action order. Old Native sequences are never reselected. SampleBest_V2 is the maximum of the seven new constant scores; historical and V2 scores are never mixed to define a gap. Score tie tolerance is1e-12. The descriptive mean-gap CI is a20000-replicate paired sample bootstrap with seed20260915. THIS CI DOES NOT ESTIMATE THE FULL 6000-SAMPLE EFFECT.

Decision guide, frozen before formal outputs: STRONG_RETENTION if GT>=150 and mean gap>0; MODERATE_RETENTION if100<=GT<150; WEAK_RETENTION ifGT<100. The unclassified edge case GT>=150 with nonpositive mean gap is MIXED_RETENTION_NONPOSITIVE_MEAN and requires interpretation. These are resource decisions, not significance thresholds. No next-stage experiment or search is authorized by these labels.
